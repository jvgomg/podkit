# US-14 — Standalone M3U directory

> Keep M3U playlist files in a dedicated directory, separate from where
> music lives, and use them as a playlist provider.

## Detail

Some users keep their playlists organised as M3U files in a curation
directory (often hand-maintained or generated by other tools). These
M3Us reference music files that live elsewhere — a separate music
library directory or even a remote source. The playlist directory itself
provides playlists, not music files.

## Acceptance signal

```toml
[sources.music]
type = "directory"
path = "/Volumes/Music"
content = "music"

[sources.m3us]
type = "directory"
path = "/Users/me/playlists"
provides = ["playlists"]
content = "music"            # the playlists reference music tracks

[devices.terapod]
music.source = "music"
music.playlist-source = "m3us"
music.collection = "my-music"
```

The collection's `filter.playlist` and `playlists` references resolve via
the standalone M3U directory.

## Notes

This depends on the playlist-files-convention being resolved — see
[open question](../open-questions/playlist-files-convention.md). Also
involves source [capabilities](../principles/source-capabilities.md):
the M3U directory claims `playlist-provider` but not music-provider.
