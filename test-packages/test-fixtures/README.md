# @podkit/test-fixtures

Test-fixture infrastructure for the podkit monorepo. Owns every synthetic audio + video file the integration and e2e suites depend on, plus the dynamic helpers used to mint one-off fixtures inside a test.

This package is internal (`"private": true`) and not published.

## Two flavours of fixtures

### 1. Static fixture sets

Pre-defined, deterministic sets of files generated by `bun run --filter @podkit/test-fixtures generate-static-fixtures`. Each set lives under `fixtures/` (gitignored — regenerated on demand and cached by turbo).

| Set | Path | Contents |
| --- | --- | --- |
| `multi-format` | `fixtures/audio/multi-format/` | 8 codec samples: WAV, AIFF, FLAC, ALAC, MP3, AAC, OGG Vorbis, Opus. 5s, deterministic metadata. No artwork. |
| `multi-format-embedded` | `fixtures/audio/multi-format-embedded/` | Same 8 tracks, each with embedded artwork via the codec's native attached-picture mechanism. No sidecar. |
| `multi-format-sidecar` | `fixtures/audio/multi-format-sidecar/` | Same 8 tracks, no embedded artwork, plus a `cover.jpg` sidecar. |
| `multi-format-both` | `fixtures/audio/multi-format-both/` | Same 8 tracks with both embedded artwork and a `cover.jpg` sidecar. |
| `goldberg-selections` | `fixtures/audio/goldberg-selections/` | 3 mono FLACs (Harmony / Vibrato / Tremolo), 20s, shared album + embedded cover. |
| `synthetic-tests` | `fixtures/audio/synthetic-tests/` | 3 mono FLACs (A440 / Sweep / Dual Tone), 15s. Track 3 has no embedded artwork. |
| `video` | `fixtures/video/` | 6 short videos covering passthrough, transcode-required, unsupported codec, and metadata-rich (movie + TV show) cases. |

The four `multi-format*` sets share the same track table (filenames, codecs, frequencies). They differ in the album tag they write — `Lossless Collection`, `Lossless Collection (Embedded)`, `… (Sidecar)`, `… (Both)` — and in their artwork configuration. The artwork test matrix in `@podkit/e2e-tests` (`art-matrix.test.ts`, `art-matrix.docker.test.ts`) exercises all four variants against both the directory and Subsonic adapters.

Tests locate fixtures by importing the lib API:

```ts
import {
  ensureFixturesExist,
  getMultiFormatFixturesDir,
} from '@podkit/test-fixtures';

// Module-level preflight — fails fast with an actionable message if the
// generator has not run yet.
ensureFixturesExist('multi-format');

const fixturesDir = getMultiFormatFixturesDir();
```

`ensureFixturesExist(set)` throws with a "run generate-static-fixtures" hint if the set has not been generated. Under normal flows it never fires: turbo wires `@podkit/test-fixtures#generate-static-fixtures` as a dependency of every `test:integration` task, so the fixtures are present by the time tests start.

### 2. Dynamic mini-track helpers

For one-off fixtures synthesised inside a test (e.g. an MP3 with a specific tag set that no static fixture covers):

```ts
import { generateMiniFlac } from '@podkit/test-fixtures';

const path = await generateMiniFlac({
  outputDir: tmpDir,
  title: 'Custom Title',
  artist: 'Custom Artist',
});
```

See `src/mini-tracks.ts` for the full options surface (artwork, duration, sample rate, etc.).

There is also a longer-form dynamic generator — `bun run --filter @podkit/test-fixtures generate-fixtures` — that produces a tagged FLAC/MP3/AAC collection into `test/manual-collection/`. That output is meant for manual demo recording (not consumed by automated tests).

## Scripts vs lib code

The distinction is intentional:

- **`scripts/`** holds files with a shebang and a top-level `main()` invocation. They are *runnable* and import from `src/`.
- **`src/`** holds library code with no top-level effects. It is type-checked as part of the `build:types` task and bundled into `dist/lib.js` for downstream consumers.

When extending the package, put the runnable CLI in `scripts/` and the underlying logic in `src/`. Keep `src/` importable without surprises.

## Regenerating

```bash
# Generate every static set (cached after the first run).
bun run --filter @podkit/test-fixtures generate-static-fixtures

# Generate one set only.
bun run --filter @podkit/test-fixtures generate-static-fixtures --only video
bun run --filter @podkit/test-fixtures generate-static-fixtures --only multi-format,goldberg-selections
```

Outputs land in this package's `fixtures/` directory. Turbo caches the task on the generator source hash — recipes only re-run when a generator file under `src/static/`, `src/encoder-guard.ts`, or `scripts/generate-static-fixtures.ts` changes.

## Required system dependencies

ffmpeg with these encoders:

| Encoder | Provided by | Used by |
| --- | --- | --- |
| `pcm_s16le`, `pcm_s16be` | ffmpeg core | multi-format (WAV, AIFF) |
| `flac` | ffmpeg core | every audio set |
| `alac` | ffmpeg core | multi-format |
| `libmp3lame` | `--enable-libmp3lame` | multi-format |
| `aac` | ffmpeg core | multi-format + video |
| `libvorbis` | `--enable-libvorbis` | multi-format |
| `libopus` | `--enable-libopus` | multi-format + video |
| `libx264` | `--enable-libx264` | video |
| `libvpx-vp9` | `--enable-libvpx` | video |
| `mjpeg` | ffmpeg core | embedded artwork + cover.jpg |

The package's `build` task runs `scripts/check-ffmpeg.ts` upfront and fails with a focused install hint if any encoder is missing. At runtime, `requireEncoder()` (`src/encoder-guard.ts`) gives the same diagnostic for in-process consumers.

Install ffmpeg with the right options:

```bash
# macOS
brew install ffmpeg

# Debian / Ubuntu
apt install ffmpeg
```

## Why the name "goldberg-selections" if the audio is synthetic?

Historic: the directory was originally intended to ship Bach's Goldberg Variations excerpts. The contents are now synthetic CC0 audio. The name has been kept so existing test fixtures keep working; track names (Harmony, Vibrato, Tremolo) describe the actual synthesis technique.
